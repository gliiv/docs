When a request fails, the Gliiv API responds with an HTTP status code and a JSON body explaining what went wrong. Every error uses the same format, so you can handle them all in one place.

## Error format

```json
{
  "message": "Invalid input provided",
  "validationErrors": {
    "phoneNumbers": "A maximum of 5 phone numbers is allowed per request"
  },
  "status": 400
}
```

| Field | Type | Description |
| :-- | :-- | :-- |
| `message` | string | A short description of the error. |
| `status` | number | The HTTP status code, repeated in the body. |
| `validationErrors` | object | Only on `400` responses. Each key is a field that failed, and its value explains why. |

## Status codes

| Status | Message | Meaning | Retry? |
| :-- | :-- | :-- | :-- |
| `200` | `Messages are being sent` | Success. The request was accepted. | — |
| `400` | `Invalid input provided` | A field is missing or invalid. `validationErrors` says which. | No. Fix the request first. |
| `401` | `Authentication required` | The API key is missing, invalid, expired, rotated or deleted. | No. Fix the key first. |
| `404` | `Sender not found` | No Sender with that ID exists on your account. | No. Fix the `senderId` first. |
| `429` | `Too many requests` | You've sent more than 60 requests in a minute with this key. | Yes, after `Retry-After` seconds. |
| `500` | `Internal server error` | Something went wrong on Gliiv's side. | Yes, after a short wait. |

## Fixing each error

| Status | What to check |
| :-- | :-- |
| `400` | Read `validationErrors`. Common causes: more than 5 numbers, a non-Rwandan number, an empty or too-long `message`, or a `senderId` that isn't a valid ID. |
| `401` | The header is named exactly `x-api-key`, the full key is included (starting with `gliiv_`), and the key still appears in **Settings → API Keys** without being expired. If you rotated the key, use the new one. |
| `404` | You're sending the Sender's **ID**, not its name. Copy it again from **Senders → ⋯ → View details**. |
| `429` | Wait the number of seconds given in the `Retry-After` response header, then send the request again. Spread requests out to stay under 60 per minute. |
| `500` | Wait a few seconds and try again. If it keeps failing, check [status.gliiv.com](https://status.gliiv.com/) or contact [hello@gliiv.com](mailto:hello@gliiv.com). |

## When to retry

Only retry `429` and `500` errors. Retrying any other error returns the same error until you fix the request.

<Warning>
  Retrying a `500` on the send endpoint can, in rare cases, send the message twice if the first request was actually processed. For messages where duplicates matter, such as one-time passwords, limit retries to one or two.
</Warning>

This example retries `429` errors after the wait given in `Retry-After`, and retries `500` errors with an increasing wait (1, 2, then 4 seconds):

<CodeGroup>

```javascript Node.js
async function sendWithRetry(body, maxRetries = 3) {
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    const response = await fetch("https://api.gliiv.com/v1/api/messages/send", {
      method: "POST",
      headers: {
        "x-api-key": process.env.GLIIV_API_KEY,
        "Content-Type": "application/json",
      },
      body: JSON.stringify(body),
    });

    if (response.ok) return response.json();

    const retryable = response.status === 429 || response.status >= 500;
    if (!retryable || attempt === maxRetries) {
      const error = await response.json();
      throw new Error(`${error.status}: ${error.message}`);
    }

    const retryAfter = Number(response.headers.get("Retry-After"));
    const waitSeconds = response.status === 429 && retryAfter ? retryAfter : 2 ** attempt;
    await new Promise((resolve) => setTimeout(resolve, waitSeconds * 1000));
  }
}
```

```python Python
import os
import time
import requests

def send_with_retry(body, max_retries=3):
    for attempt in range(max_retries + 1):
        response = requests.post(
            "https://api.gliiv.com/v1/api/messages/send",
            headers={"x-api-key": os.environ["GLIIV_API_KEY"]},
            json=body,
        )

        if response.ok:
            return response.json()

        retryable = response.status_code == 429 or response.status_code >= 500
        if not retryable or attempt == max_retries:
            error = response.json()
            raise RuntimeError(f"{error['status']}: {error['message']}")

        retry_after = response.headers.get("Retry-After")
        if response.status_code == 429 and retry_after:
            wait_seconds = int(retry_after)
        else:
            wait_seconds = 2 ** attempt
        time.sleep(wait_seconds)
```
